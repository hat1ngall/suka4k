# Mupple: запуск сайта и базы на Render

В этом проекте лежат сайт (`public/`), сервер Node.js и PostgreSQL. Работают регистрация с никнеймом, вход и выход; подтверждения почты и восстановления пароля пока нет. Новые пароли хранятся как хеши scrypt. Проект также умеет проверять хеши аккаунтов, созданных на текущем сайте Sites, после импорта этих аккаунтов. Сессии между площадками не переносятся: после импорта потребуется войти снова.

## Публикация

1. Распакуйте архив. Создайте отдельный **приватный** GitHub-репозиторий и загрузите в его корень *содержимое* папки `voreq-account` (файлы `render.yaml`, `package.json`, `server.js` и папки `public`, `scripts` и `test` должны оказаться в корне). Не загружайте файл экспорта аккаунтов, `.env` и пароли в репозиторий.
2. Зарегистрируйтесь или войдите на Render, подключите GitHub в настройках Render и дайте Render доступ к созданному репозиторию.
3. На панели Render выберите **New → Blueprint**, выберите репозиторий и подтвердите найденный `render.yaml`. Blueprint подготовит веб-сервис `voreq-web` и отдельную базу `voreq-db`; Render автоматически передаст приложению внутренний `DATABASE_URL`.
4. До подтверждения проверьте стоимость: в `render.yaml` веб-сервис выбран на плане Free, а база Postgres `0.1c-256mb` — **платная**. Вы не обязаны создавать ресурсы до согласия с ценой. Вы можете для временного теста изменить план базы в `render.yaml` на `free`, но бесплатная база Render истекает через 30 дней, после чего доступ ограничен и данные могут быть удалены после льготного периода. Сведения и актуальные тарифы: https://render.com/docs/free и https://render.com/pricing.
5. Дождитесь окончания сборки и откройте URL веб-сервиса, заканчивающийся на `onrender.com`. Это будет отдельный, доступный по ссылке сайт; исходный сайт Sites при этом не меняется. Сайт должен раздаваться **Web Service**, а не Static Site: сервер нужен для аккаунтов.
6. Таблицы создаются сервером при запуске. Проверьте открытие главной, документов, создание тестового аккаунта, выход и повторный вход. Пароль и коды не отправляйте в чат.

Бесплатный веб-сервис Render засыпает после 15 минут без запросов и может просыпаться около минуты. База — отдельная от сервера, поэтому её данные не исчезают при закрытии посетителями сайта или перезапуске веб-сервиса. При тарифе Free действуют ограничения https://render.com/docs/free. На платной базе возможны расходы на вычисления и хранение; уточните итог в Render до создания.

## Перенос существующих аккаунтов Sites

На время подготовки проекта экспортированы текущие строки таблицы аккаунтов в **отдельный закрытый файл** `voreq-accounts-private.json`, который не включён в архив сайта. На момент экспорта в базе был один технический тестовый аккаунт. Если после экспорта на старом сайте кто-либо зарегистрируется, для переноса понадобится новая выгрузка; две базы автоматически не синхронизируются. Пароли в выгрузке находятся только в хешированном виде, однако файл содержит адреса и хеши — храните его как секрет и никогда не выкладывайте в GitHub и не отправляйте посторонним.

Импорт запускается **после** первого успешного запуска Render-сайта и создания таблиц. Для запуска с компьютера потребуется Node.js, внешняя строка подключения к Render Postgres с TLS и правило сети, разрешающее только ваш IP-адрес. В `render.yaml` внешние подключения по умолчанию закрыты. Настройку доступа и строку подключения найдите в панели Render Postgres; не публикуйте и не присылайте пароль. Документация: https://render.com/docs/postgresql-creating-connecting и https://render.com/docs/blueprint-spec#inbound-ip-rules.

В PowerShell, находясь в папке проекта (после `npm ci`), установите `DATABASE_URL` через защищённый ввод или локальное окружение, не сохраняя его в репозитории; используйте TLS (`sslmode=require`). Затем выполните:

```powershell
node scripts/import-sites-users.mjs 'C:\путь\к\voreq-accounts-private.json'
```

Скрипт импортирует строки в одной транзакции, пропускает уже существующие email и не переносит активные сессии. После импорта закройте временное внешнее сетевое правило. Без доступа к фактической базе Render перенос нельзя выполнить и проверить: создание архива ещё не означает, что аккаунты уже перенесены.

## Локальный запуск и проверка

Установите Node.js 20+ и PostgreSQL, создайте пустую БД. В PowerShell:

```powershell
npm ci
$env:DATABASE_URL = 'postgresql://postgres:password@localhost:5432/voreq'
$env:NODE_ENV = 'development'
npm start
```

Откройте http://localhost:3000. Файл `.env.example` — пример; сервер читает переменные окружения и не загружает `.env` автоматически. `npm test` проверяет хеширование, импортируемый формат пароля, работу HTTP и сессий на имитации базы; для интеграционной проверки настоящей PostgreSQL задайте `TEST_DATABASE_URL` на отдельную тестовую БД с правами CREATE SCHEMA и выполните `npm test`. Не используйте производственную базу для тестов.

Ограничитель попыток входа хранится в памяти процесса и обнуляется после перезапуска; при нескольких экземплярах нужен общий rate-limit store. Отдельно настройте резервное копирование и проверьте юридические документы перед запуском для пользователей.


### Админ-панель промокодов

В настройках Web Service в Render добавьте переменную окружения `ADMIN_PASSWORD` со случайным уникальным паролем длиной не менее 16 символов и перезапустите сервис. Не добавляйте пароль в репозиторий. Панель доступна по адресу `/admin`: после входа можно создавать и отключать промокоды. Проверка промокодов и отображение скидки в корзине работают, но платёжный сервис пока не подключён. При подключении платежей сервер должен повторно проверять промокод и сам рассчитывать итоговую стоимость; данным корзины в браузере доверять нельзя.
